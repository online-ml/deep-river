# AGENTS.md

## Rules for coding agents

1. **Write code, not comments.** You may generate code, using the existing codebase for idiomatic examples to draw from. Do not write comments. Encourage humans to write comments themselves, to force them to understand the code you've written.
2. **Prose is written by humans, not by you.** Issues, pull request descriptions, commit messages, docstrings, and release-note entries must all be typed out by a human, in their own words. You may run a benchmark and produce a summary table, but a human must editorialize it and fold it into a message they wrote themselves.
3. **Disclose agent-written code.** Code generated by an agent must be marked as such. Do not pass it off as hand-written. A `Co-authored-by:` trailer on the commit is the simplest way.
4. **Be thorough on tests.** Tests are often longer than the implementation and tedious to write. With an agent there is no excuse for skipping them. The minimum for new estimators is to pass `utils.check_estimator`. Ideally you should add out-of-the-box tests to check for edge cases.

## What is deep-river?

deep-river is a Python library for online deep learning. It combines River's online machine learning API with PyTorch modules, so estimators can learn incrementally through `learn_one`/`predict_one` methods and, where supported, `learn_many`/`predict_many` mini-batch methods.

## Common commands

```sh
# Install / sync dependencies, including development dependencies
uv sync --extra dev

# Run tests, including doctests from modules and README.md
uv run pytest

# Run the project test target
make test

# Run a single test file
uv run pytest tests/utils/test_tensor_conversion.py

# Lint and format via pre-commit hooks
make format

# Type checking
uv run mypy deep_river

# Build docs locally
make doc

# Build and serve docs locally
make livedoc

# Execute notebooks in place
make execute-notebooks
```

## Architecture

### Base classes (`deep_river/base.py`)

All deep estimators build on `DeepEstimator`, which wraps a `torch.nn.Module` and adapts it to River's estimator API. `RollingDeepEstimator` extends this with a fixed-size rolling buffer for sequence-style models.

Key modules:
- `deep_river.classification` - incremental classifiers, including rolling classifiers and zoo models
- `deep_river.regression` - incremental regressors, multi-target regressors, rolling regressors, and zoo models
- `deep_river.anomaly` - autoencoder-based anomaly detectors and scalers
- `deep_river.utils` - tensor conversion, loss/optimizer resolution, hooks, inspection helpers, and estimator checks

### Estimator conventions

- `learn_one(x, y)` / `predict_one(x)` is the core online learning interface for supervised estimators.
- `learn_many(X, y)` / `predict_many(X)` is used for mini-batch support where implemented.
- Unsupervised anomaly detectors implement `learn_one(x)` and `score_one(x)`.
- PyTorch modules are passed in through the `module` parameter and should define a `forward` method compatible with the tensors produced by deep-river.
- `__init__` parameters need type hints; provide defaults or implement `_unit_test_params()`.
- `_unit_test_skips()` returns check names to skip in automated testing.
- Feature-incremental models can expand input layers when new feature names appear.
- Class-incremental classifiers can expand output layers when new classes appear.
- Target-incremental multi-target regressors can expand output layers when new target names appear.

### Estimator testing framework (`deep_river/utils/`)

- `utils.check_estimator(MyEstimator)` runs River's estimator checks together with deep-river checks for tensor conversion, learning, and persistence.
- `tests/utils/test_estimators.py` discovers estimators and runs the project-wide estimator checks.
- Pytest is configured with `--doctest-modules` and `--doctest-glob='README.md'`, so docstring examples and README examples are executed as tests.

### Documentation and benchmarks

- Documentation is built with Zensical and generated from `docs/` plus API reference pages created by `docs/scripts/gen_ref_pages.py`.
- Benchmark CSVs are rendered into the docs by `benchmarks/render.py`, which is called by the docs Makefile targets.
